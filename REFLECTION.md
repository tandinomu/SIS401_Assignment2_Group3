# Reflection - SIS401 Assignment 2 (Group 3)

**Design decisions.** The main decision was to make the Raspberry Pi the only gateway to the cloud. The ESP32 publishes only to the local Mosquitto broker, and Node-RED forwards the data to ThingsBoard. This keeps the cloud access token off the microcontroller, keeps the firmware simple, and lets the local dashboard keep working if the internet drops. The fields `dht_ok`, `rssi` and `uptime_s` were added to the payload so that failed sensor reads, weak WiFi and unexpected resets are visible instead of hidden. The same 30 °C threshold appears in two places. The ESP32 lights the LED immediately without waiting for the network, while ThingsBoard keeps an alarm record that can be reviewed later.

**Challenges.** Mosquitto 2.x refused outside connections until a listener on `0.0.0.0` with anonymous access was configured. Finding the Pi was also confusing at first: `ping sis401pi.local` returned an IPv6 address, but the ESP32 needed IPv4, which `ping -4` provided. The lab network was unreliable, so the whole system ran on a mobile hotspot. Calibrating the LDR took some trial and error, because its output is inverted (a higher raw value means darker). The servo caused voltage drops on the supply, which a capacitor across the rail reduced.

**Improvements.** Anonymous MQTT is acceptable on a private hotspot but not in real use. The local broker should use username and password authentication with TLS, and the link to ThingsBoard should use MQTTS on port 8883. Buffering readings on the Pi while the cloud is unreachable would prevent data loss. Moving the actuator to ThingsBoard RPC would allow control from anywhere, not only from the local dashboard. With more time, the Edge Impulse extension could classify room comfort directly on the ESP32.
